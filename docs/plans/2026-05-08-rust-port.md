# CLI Printing Press Rust Port Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Build a Rust-native counterpart to the Printing Press that preserves the core pipeline — research, spec ingestion, generation, verification, and publishing — while reducing startup overhead, memory churn, and generated-binary runtime cost.

**Architecture:** Keep the existing Go codebase as the source-of-truth reference and treat the Rust codebase as a clean-room compatibility port. Start with a parallel spike under `rust-port/` instead of touching the Go machine. Mirror the high-level command surface first, then port deterministic subsystems in descending leverage order: spec loading, pipeline state, code generation, verification, and MCP emission.

**Tech Stack:** Rust 2024 edition, `clap` for CLI, `tokio` for async orchestration, `serde`/`serde_yaml`/`serde_json` for data models, `reqwest` for HTTP, `tracing` for logs, `anyhow` + `thiserror` for errors.

---

## Scope notes

- This is a port, not a wrapper around the Go binary.
- The Rust spike lives beside the Go machine until parity is proven.
- The first milestone is command-shape and pipeline-shape compatibility, not full feature parity.
- Success means we can run a deterministic subset of the pipeline entirely in Rust and compare artifacts against the Go machine.

## Milestones

### Milestone 1: Rust skeleton and command contract

**Objective:** Create a compilable Rust CLI with the same top-level mental model as the Go binary.

**Files:**
- Create: `rust-port/Cargo.toml`
- Create: `rust-port/src/main.rs`
- Create: `rust-port/src/cli.rs`
- Create: `rust-port/src/commands/mod.rs`
- Create: `rust-port/README.md`

**Verification:**
- Run: `cargo check --manifest-path rust-port/Cargo.toml`
- Expected: pass
- Run: `cargo run --manifest-path rust-port/Cargo.toml -- --help`
- Expected: command list renders with placeholders for core pipeline verbs

### Milestone 2: Deterministic spec ingestion

**Objective:** Port YAML/OpenAPI loading and slug/naming normalization.

**Files:**
- Create: `rust-port/src/spec/mod.rs`
- Create: `rust-port/src/spec/openapi.rs`
- Create: `rust-port/src/spec/naming.rs`
- Create: `rust-port/tests/spec_ingest.rs`

**Verification:**
- Use the repo's existing deterministic fixtures under `testdata/golden/fixtures/`
- Compare Rust slug generation and spec-kind detection against the Go output

### Milestone 3: Pipeline state and artifact paths

**Objective:** Port the non-networking pipeline bookkeeping so the Rust binary can resolve output paths, run IDs, and manuscript structure exactly once.

**Files:**
- Create: `rust-port/src/pipeline/mod.rs`
- Create: `rust-port/src/pipeline/state.rs`
- Create: `rust-port/src/pipeline/paths.rs`
- Create: `rust-port/tests/pipeline_paths.rs`

**Verification:**
- Compare generated paths for the same sample specs with the Go machine
- Expected: identical slugging and deterministic path layout

### Milestone 4: Generation core

**Objective:** Emit a minimal printed CLI from a spec in Rust.

**Files:**
- Create: `rust-port/src/generator/mod.rs`
- Create: `rust-port/src/generator/render.rs`
- Create: `rust-port/templates/`
- Create: `rust-port/tests/generate_smoke.rs`

**Verification:**
- Generate into a temp directory from one golden fixture spec
- Expected: Rust output builds and matches an agreed minimal contract

### Milestone 5: Verification and scorecard

**Objective:** Port the deterministic quality gates that provide the machine's confidence loop.

**Files:**
- Create: `rust-port/src/verify/mod.rs`
- Create: `rust-port/src/scorecard/mod.rs`
- Create: `rust-port/tests/verify_contract.rs`

**Verification:**
- Reproduce a subset of `dogfood`, `verify`, and `scorecard` on golden fixtures
- Expected: same pass/fail verdicts on deterministic cases

## Constraints

- Keep the Rust code isolated under `rust-port/` until parity is real.
- Do not rewrite the Go machine in place.
- Prefer deterministic fixtures before live API testing.
- Preserve the Printing Press vocabulary and artifact model.
